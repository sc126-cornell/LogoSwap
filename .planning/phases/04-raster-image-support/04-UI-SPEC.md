# Phase 4 — UI Design Contract (Delta-only)

> Visual and interaction contract for the 點陣圖與圖片型檔案支援 (raster & image-type file support) phase.
> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **這是一份 delta-only 契約。** Phase 4 後端工作量極大(ingest dispatch、影像 → A4 PDF 正規化、raster redact 分支、image-overlap 偵測),但 UI 變動極小:單一 dropzone 的 `accept` / copy / aria-label 從「PDF only」擴展為「PDF + 影像」,並為三個新後端錯誤碼補上繁中文案。Phase 1 已建立的 token(色、字、間距)、Phase 2 的框選 overlay、Phase 3 的 logo picker / 套用後鎖框 / 整份 90° 旋轉 — **全部完整繼承,不重新規範**。
>
> **UI language:** 所有對使用者顯示的字串為繁體中文。
>
> **D-07 contract:** 偵測到的「向量 / 點陣 / 掃描」模式 **不在 UI 任何位置揭露** — 沒有 badge、沒有副本、沒有 hover tooltip。使用者只看到「上傳 → 框選 → 套用 → 下載」一條線。任何在這份 UI-SPEC 之外被加上的「raster/vector/scan」分類視覺,屬於違反此契約,checker 應 FAIL。

## Phase 4 Surface Delta(本檔唯一新增之處)

Phase 4 對 UI 的修改只有兩塊:

1. **Dropzone(empty state)**:`accept` / `dropzone__heading` / `dropzone__body` / `dropzone__hint` / `aria-label` / file-picker button label 五處字串與屬性。
2. **Inline error block 文案表(`error-body`)**:對三個新後端錯誤碼(`unsupported_image_format`、`multi_page_tiff_unsupported`、`corrupt_image`)新增繁中文案。Phase 1 既有的 unsupported / corrupt / 過大 / 上傳失敗錯誤訊息全部沿用,本檔不重述。

下游頁面(`/pages/{n}/image` 回的 PNG、框選 overlay、logo picker、結果預覽、下載)對影像化檔案是 zero-difference,不需要任何視覺或互動變更。

## Copywriting Contract(Phase 4 delta)

所有對使用者顯示的字串為繁體中文。括號內英文為 planner/executor gloss,不得進入 UI。

### Dropzone — Empty state(`web/index.html` 第 ~283–298 行)

| Element | Phase 1 copy | Phase 4 copy(本檔鎖定)|
|---------|-------------|--------------------------|
| `dropzone__heading`(`<h2>`)| 上傳 PDF 以開始 | **上傳 PDF 或影像以開始** |
| `dropzone__body`(`<p>`)| 選擇或拖曳一個供應商 PDF 檔案,即可在此預覽各頁內容。原始檔案不會被更動。 | **選擇或拖曳一個 PDF 或影像檔案(PNG、JPG、TIFF),即可在此預覽並框選要替換的商標。原始檔案不會被更動。** |
| `#choose-file`(primary CTA)| 選擇 PDF 檔案 | **選擇檔案** |
| `dropzone__secondary`(`<p>`)| 或將檔案拖曳到這裡 | **或將檔案拖曳到這裡**(不變,沿用 Phase 1)|
| `dropzone__hint`(`<p>`)| 支援 PDF 檔(單一檔案)| **支援 PDF、PNG、JPG、TIFF(單一檔案)** |
| `#dropzone` `aria-label` | 選擇 PDF 檔案 | **選擇 PDF 或影像檔案** |
| `#file-input` `accept` | `application/pdf,.pdf` | **`application/pdf,.pdf,image/png,image/jpeg,image/tiff,.png,.jpg,.jpeg,.tif,.tiff`** |

**Glosses(英文,**不進 UI**):**
- heading:"Upload a PDF or image to begin"
- body:"Choose or drag a PDF or image file (PNG, JPG, TIFF) to preview it and frame the logos to replace. Your original file is never modified."
- CTA:"Choose file"(刻意去除 "PDF" 字眼,因為現在也接受影像)
- hint:"Supports PDF, PNG, JPG, TIFF (single file)"
- aria-label:"Choose PDF or image file"

**寫作理由:**
- heading 故意先 PDF 後影像,反映核心場景(供應商 PDF 為主、影像為次)— 但保持兩者並列、不暗示影像是「次等」。
- body 把「預覽各頁內容」改為「預覽並框選要替換的商標」,因為 Phase 4 上線時 Phase 2/3 已就緒,empty state 文案應指向完整流程,而非只到預覽。
- CTA 從「選擇 PDF 檔案」改成「選擇檔案」— Phase 1 的 CTA 是限定詞短句(verb + noun + qualifier),Phase 4 多型別後 qualifier 反而誤導,故只保留 verb + noun。本變更與 D-11 一致。
- hint 列出四個型別,**不**列副檔名變體(`.tif` vs `.tiff` 細節不對使用者顯示);accept 屬性的副檔名變體屬瀏覽器層,使用者不需看到。

### Inline error block — 三個新錯誤碼(`web/js/api.js` ↔ `app.js` 對應的 `error-body` 文案)

新增三個錯誤碼,對應後端 `IngestError(code, message)`(D-12 of CONTEXT + RESEARCH Question 5)。沿用 Phase 1 既有 `.error-block` 結構(`error-block__icon` + `error-heading` + `error-body` + `error-retry`)— **不新增視覺結構**。

文案規則一律遵循 Phase 1 已建立的「**問題描述 + 下一步**」 pattern。

| 後端錯誤碼 | HTTP | `error-heading`(沿用 Phase 1)| `error-body`(Phase 4 鎖定) | Gloss(不進 UI) | 重試按鈕 |
|------------|------|------------------------------|------------------------------|-------------------|---------|
| `unsupported_image_format` | 415 | 無法開啟此檔案 | **此影像格式不支援。請改用 PDF、PNG、JPG 或 TIFF 檔案後再試一次。** | "This image format isn't supported. Please use a PDF, PNG, JPG, or TIFF file and try again." | 顯示(`重試` — 沿用 Phase 1 既有按鈕)|
| `multi_page_tiff_unsupported` | 415 | 無法開啟此檔案 | **暫不支援多頁 TIFF。請先將 TIFF 拆成單頁後再上傳。** | "Multi-page TIFF isn't supported. Please split the TIFF into single-page files first." | 顯示 |
| `corrupt_image` | 422 | 無法開啟此檔案 | **這個影像檔案無法讀取,可能已損毀。請確認檔案後再試一次。** | "This image can't be read and may be damaged. Check the file and try again." | 顯示 |

**寫作理由:**
- 三個錯誤皆沿用既有 `error-heading`「無法開啟此檔案」(Phase 1 一致),不為新型別自創 heading variant。使用者第一眼看到的是「開不起來」,具體 why 由 body 句子提供。
- `multi_page_tiff_unsupported` 的「下一步」明確告知**動作**(「拆成單頁」)而非「換一個檔」 — 因為使用者通常已經有那個 TIFF,給更具體的 work-around。
- `corrupt_image` 的措辭與 Phase 1 既有的 `corrupt_pdf`「這個 PDF 檔案無法讀取,可能已損毀…」**字級對齊**(同一句型,差別只是名詞),維持錯誤文案的家族一致性。
- `unsupported_image_format` 與 Phase 1 既有的 `unsupported_type`(「此檔案格式不支援。請改用 PDF 檔案後再試一次。」)**家族一致** — 但下一步從「改用 PDF」改為「改用 PDF、PNG、JPG 或 TIFF」反映 Phase 4 真正接受的範圍。

### Sniff 失敗(`unsupported_type` — 既有錯誤碼,文案需微調)

Phase 4 後端 ingest 在 magic-sniff 階段拒絕「不在四種 magic 列表內」的檔案(例如 GIF / WebP / SVG / 純文字 / ELF),仍 raise 既有 `unsupported_type` 4xx(D-12)。Phase 1 的文案需 mirror dropzone hint 一同更新:

| 錯誤碼 | Phase 1 copy | Phase 4 copy(本檔鎖定)|
|--------|-------------|--------------------------|
| `unsupported_type` | 此檔案格式不支援。請改用 PDF 檔案後再試一次。 | **此檔案格式不支援。請改用 PDF、PNG、JPG 或 TIFF 檔案後再試一次。** |

### Empty state body(`empty-state-body`)的「Phase 1 reassurance」

Phase 1 既有 body 已含「原始檔案不會被更動」reassurance,Phase 4 改寫的 dropzone body 必須**保留**這句(D-05 of project = SHA-256 D-05 保證)— 上方文案表已照此處理。

### Destructive actions

| Element | Copy |
|---------|------|
| (none — 本 phase 無新增 destructive action)| Phase 4 沒有新增任何 destructive UI。「清除全部框選」確認對話框、「更換檔案」soft confirmation 全沿用 Phase 1/2,**字串不變**(「更換檔案」對影像型檔案語意上仍對:使用者想換一個新檔案,不管原來是 PDF 還是影像)。 |

## Layout & Interaction Contract(Phase 4 delta)

- **Empty state focal point**:仍為單一 CTA(`選擇檔案` 按鈕),accent fill,page-stage 正中。Phase 1 已建立的「一個 state 一個 focal point」原則不變。新增 hint 文案不爭奪視覺份量(`--font-size-label` / `--color-text-muted`)。
- **Dropzone drag-over feedback**:沿用 Phase 1(accent-tinted 邊框)— **不**因檔案類型新增多色回饋(避免在 drag 階段就洩漏「raster/vector」分類)。
- **Upload → preview 流程**:對影像型檔案(PNG/JPG/TIFF)後端在 ingest 階段同步做 image → A4 PDF 正規化(D-01),前端對使用者**沒有任何「正在正規化…」中介狀態**;沿用 Phase 1 既有的 `正在上傳檔案…` → `正在處理檔案,準備預覽…` 兩段 loader 即可覆蓋。新狀態不引入。
- **Error 回饋的非阻擋性**:三個新錯誤碼出現時,inline error block 出現在 page-stage 中央,**重試** 按鈕回到 dropzone empty state — 沿用 Phase 1 既有狀態機,新錯誤不改變狀態流。
- **下載檔名顯示**:瀏覽器原生下載 prompt 顯示後端 `Content-Disposition` 的檔名(D-13:`<stem>_logoswap.pdf`)。前端不再覆蓋 — 沿用 Phase 2。
- **整份 90° 旋轉互動**:對影像型檔案(A4 portrait)同樣可用。使用者上傳的橫向影像若被 D-01 fit 成 portrait A4 並留大量白邊,可用既有「整份順 / 逆時針 90°」鈕轉成 landscape orientation — **此互動沿用 Phase 3,不需 Phase 4 新增任何快捷鍵或 hint 文案**(D-09 of RESEARCH:始終 portrait A4,讓使用者自己用整份 90° 旋轉切換)。
