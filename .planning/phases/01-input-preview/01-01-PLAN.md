API endpoints (all paths relative to configurable API base):

POST /sessions
  - request: multipart/form-data, field name "file" (single file)
  - success 201: { "session_id": str, "page_count": int, "filename": str }
  - error 4xx: { "detail": { "code": str, "message": str } }
    codes: "unsupported_type" (415), "file_too_large" (413), "corrupt_pdf" (422), "empty_file" (400)

GET /sessions/{session_id}
  - success 200: { "session_id": str, "page_count": int, "filename": str }
  - error 404: { "detail": { "code": "session_not_found", "message": str } }

GET /sessions/{session_id}/pages/{page_no}/image?dpi=<int>
  - page_no is 0-based; dpi optional, defaults to config.DEFAULT_DPI, clamped to [config.MIN_DPI, config.MAX_DPI]
  - success 200: image/png body
  - response headers carry page metadata for the coordinate seam (Phase 2 reads these):
      X-Page-Width-Pt, X-Page-Height-Pt, X-Page-Rotation, X-Render-Dpi, X-Image-Width-Px, X-Image-Height-Px
  - error 404: session or page not found

GET /sessions/{session_id}/pages/{page_no}/meta
  - success 200: { "page_no": int, "page_w_pt": float, "page_h_pt": float, "rotation": int, "dpi": int, "img_w": int, "img_h": int }
  - Provided so the frontend can size the page stage BEFORE the image loads (no letterbox/detach).

GET /health
  - success 200: { "status": "ok" }

Pydantic models (app/models.py):
  SessionInfo { session_id: str, page_count: int, filename: str }
  PageMeta { page_no: int, page_w_pt: float, page_h_pt: float, rotation: int, dpi: int, img_w: int, img_h: int }
  ErrorDetail { code: str, message: str }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/LAN client → POST /sessions | Untrusted file bytes + client-supplied filename cross here. No auth (internal LAN), so treat every caller as untrusted. |
| Uploaded bytes → PyMuPDF (MuPDF C parser) | Untrusted binary parsed by a C-backed library — a known attack/crash surface. |
| Client filename → filesystem path | Client-controlled string must never become a path component. |
| work/ editing copy ↔ originals/ immutable source | Internal boundary; the original must remain byte-for-byte intact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Denial of Service | POST /sessions upload size | mitigate (HIGH) | Enforce `MAX_UPLOAD_BYTES` (default 50 MB) while reading the stream; reject oversize with 413 `file_too_large` before buffering the whole file. Implemented in `ingest.ingest_upload` + the route (Task 1/2). |
| T-01-02 | Denial of Service | Page count / page size | mitigate (HIGH) | Reject `page_count > MAX_PAGE_COUNT` (Task 1). Clamp render `dpi` to `[MIN_DPI, MAX_DPI]` so a caller cannot request a multi-gigabyte pixmap (Pitfall 8) (Task 2). |
| T-01-03 | Tampering | PyMuPDF parsing malformed/malicious PDF | mitigate (HIGH) | All `fitz.open`/parse calls wrapped in try/except in `pdf_engine.py`; failures become typed `PdfEngineError` → structured 422 `corrupt_pdf`, never a 500/crash that takes down the worker (Pitfall 11). Pin a current PyMuPDF for CVE fixes. |
| T-01-04 | Tampering / Elevation | Client filename → path traversal | mitigate (HIGH) | `storage.sanitize_filename` strips directory components and `..`; server generates the session dir name (`secrets.token_urlsafe`); the client filename is never used as a path (Task 1). Tested with `../../etc/passwd`. |
| T-01-05 | Tampering | In-place mutation of the original (UPLOAD-04) | mitigate (HIGH) | Original written write-once and chmod read-only; all processing opens only the `work/` copy; render reads work copy. Tests assert original hash unchanged after ingest + render (Anti-Pattern 3, Pitfall 9) (Task 1/2). |
| T-01-06 | Spoofing (type confusion) | Extension-trusted upload | mitigate | Content-sniff the PDF header / successful parse rather than trusting the `.pdf` extension; non-PDF → 415/422 (Task 1). |
| T-01-07 | Information Disclosure | One LAN user reading another's session via guessable id/path | mitigate (MEDIUM) | `session_id` is a 128-bit `token_urlsafe` (unguessable), not a sequential counter; files live under per-session dirs (Task 1). Full auth deferred (v1 internal LAN, accepted). |
| T-01-08 | Information Disclosure | Stack traces leaking internals on error | mitigate | Global exception handler returns only `{code, message}`; internal exception text is not surfaced to the client (Task 2). |
| T-01-09 | Repudiation | No audit log | accept | Internal single-purpose LAN tool, no auth, no compliance requirement in v1. Revisit at the website-embedding milestone. |
| T-01-10 | Denial of Service | Stale temp/session files filling disk | accept (this phase) | Retention janitor is explicitly Phase 5. Per-session dirs make later cleanup trivial. Accepted for Phase 1; flagged for Phase 5. |
</threat_model>
