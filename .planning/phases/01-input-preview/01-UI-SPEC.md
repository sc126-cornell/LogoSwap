# Phase 1 — UI Design Contract

> Visual and interaction contract for the 輸入與預覽骨幹 (input & preview skeleton) phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **UI language:** All user-facing strings are Traditional Chinese (繁體中文). English glosses in parentheses are for the planner/executor only and MUST NOT ship in the UI.
>
> **Non-interactive run:** No CONTEXT.md from discuss-phase exists and the researcher could not prompt the user. Every value below is a justified DEFAULT for a clean, professional internal document-tooling web app, marked "default — confirm later". The codebase is greenfield (no existing tokens/components were found), so this establishes the FOUNDATIONAL token set that Phases 2–5 will reuse.

---

## Phase Scope (what this contract covers)

Phase 1 delivers ONLY upload-one-file + preview-it. The contract therefore covers exactly these surfaces:

| Surface | In this phase | Notes |
|---------|---------------|-------|
| Upload control (single file) | Yes | Vector PDF is the v1 target. The control must NOT preclude image-type PDF or standalone PNG/JPG/TIFF (Phase 4) — accept-list and copy are written to extend. |
| Preview viewer (server-rendered PNG `<img>`) | Yes | Browser shows the exact PNG the backend rasterized via PyMuPDF `get_pixmap`. No client-side PDF parsing/rendering. |
| Multi-page navigation | Yes | Previous/Next, current-page indicator, jump-to-page input. |
| Zoom | Yes | Discrete zoom steps + fit-to-width; re-requests a higher-DPI render or CSS-scales the image (executor's call, see Component Inventory). |
| Loading / Empty / Error states | Yes | Upload-in-progress + page-render-in-progress loading; pre-upload empty state; invalid/failed-file error state. |
| Region drawing / removal / logo placement | NO — Phases 2–4 | Do NOT design here. BUT: choose layout + tokens that extend to a transparent canvas-overlay region selector over the page image, and a right-hand side panel (region list / logo picker) later. |

**Forward-compatibility requirement (load-bearing):** The preview viewer must be built as a positioned **page stage** (a relatively-positioned container holding the page `<img>`) so a future absolutely-positioned transparent overlay `<canvas>`/`<div>` can sit pixel-aligned on top without layout changes. The app shell must reserve a collapsible right **side-panel** column (empty/hidden in Phase 1) so Phase 2's region list and Phase 3's logo picker drop in without re-architecting the grid.

## Spacing Scale

8-point scale (CSS custom properties on `:root`). All declared values are multiples of 4.

| Token | CSS var | Value | Usage |
|-------|---------|-------|-------|
| xs | `--space-xs` | 4px | Icon-to-label gaps, inline padding inside compact controls |
| sm | `--space-sm` | 8px | Spacing between tight controls (e.g. prev/next buttons), input inner padding |
| md | `--space-md` | 16px | Default gap between elements; card/panel inner padding |
| lg | `--space-lg` | 24px | Section padding; gap between toolbar groups; app-shell gutter |
| xl | `--space-xl` | 32px | Layout gaps between major regions (toolbar ↔ stage) |
| 2xl | `--space-2xl` | 48px | Major vertical breaks; empty-state vertical rhythm |
| 3xl | `--space-3xl` | 64px | Page-level outer spacing; empty-state top offset on large viewports |

**Exceptions:**
- Interactive control minimum hit target: **40px** height for buttons and the page-jump input (comfortable mouse target for a desktop LAN tool; 40 is a multiple of 4). Icon-only buttons (prev/next, zoom +/−) are **40×40px**. This is a control-sizing minimum, not a new spacing step.

## Typography

System UI font stack (no web-font fetch); CJK-aware so 繁體中文 renders with the OS Chinese UI face.

```
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI",
             "Microsoft JhengHei", "PingFang TC", "Noto Sans TC",
             Roboto, Helvetica, Arial, sans-serif;
```

Exactly 4 sizes, exactly 2 weights.

| Role | CSS var | Size | Weight | Line Height | Usage |
|------|---------|------|--------|-------------|-------|
| Display | `--font-size-display` | 28px | 600 (semibold) | 1.2 | Empty-state headline only |
| Heading | `--font-size-heading` | 20px | 600 (semibold) | 1.25 | App title bar, panel/section headings |
| Body | `--font-size-body` | 16px | 400 (regular) | 1.5 | Default text, error body copy, button labels |
| Label | `--font-size-label` | 14px | 400 (regular) | 1.4 | Page indicator, captions, helper/hint text, tooltips |

| Weight | CSS var | Value |
|--------|---------|-------|
| Regular | `--font-weight-regular` | 400 |
| Semibold | `--font-weight-semibold` | 600 |

Notes: numeric page indicator (e.g. `3 / 12`) uses `font-variant-numeric: tabular-nums` so digits don't jitter while paging.

## Color

Neutral, professional, **minimalist** palette with a single restrained accent. 60/30/10 split. **Both light and dark themes, user-toggleable — confirmed in 01-CONTEXT.md (D-05–D-07).** The table below is the LIGHT theme; the dark theme is defined in the Dark Theme subsection.

| Role | CSS var | Value | Usage |
|------|---------|-------|-------|
| Dominant (60%) | `--color-surface` | `#F5F6F8` | App background / preview stage backdrop (neutral light grey so a white PDF page reads as a distinct, shadowed sheet) |
| Secondary (30%) | `--color-panel` | `#FFFFFF` | Toolbar, side panel, cards, upload dropzone fill, dialog surface |
| Accent (10%) | `--color-accent` | `#2563EB` | See "Accent reserved for" — primary action + active page indicator ONLY |
| Accent hover | `--color-accent-hover` | `#1D4ED8` | Hover/active state of the accent primary button |
| Destructive | `--color-danger` | `#DC2626` | Error-state text/icon and (future) destructive-confirm button. Not used as a fill in Phase 1. |

Supporting neutrals (not part of the 10% accent budget):

| Role | CSS var | Value | Usage |
|------|---------|-------|-------|
| Text primary | `--color-text` | `#1F2933` | Headings, body |
| Text secondary | `--color-text-muted` | `#6B7280` | Labels, hints, page indicator, empty-state body |
| Border / divider | `--color-border` | `#D9DCE1` | Control borders, panel/toolbar dividers, dropzone outline |
| Focus ring | `--color-focus-ring` | `#2563EB` | 2px keyboard-focus outline (matches accent; applies to all focusable controls) |
| Overlay scrim | `--color-scrim` | `rgba(15, 23, 42, 0.45)` | Dim behind a modal error dialog / blocking loader, if used |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The **primary upload / confirm action** — the main "選擇檔案 / 上傳" button (and the dropzone's primary CTA).
2. The **active / current page indicator** — the highlighted current page number in the page navigator.

Everything else interactive (prev/next, zoom, jump-to-page input, secondary buttons) uses neutral surfaces with `--color-border` and a neutral hover (`#EDEFF2`), NOT the accent. Secondary buttons are outline/ghost style. The focus ring uses the accent hue but is a focus affordance, not a 10%-budget fill.

### Dark theme (light/dark toggle — D-06/D-07)

A user-toggleable light/dark theme. Initial theme follows `prefers-color-scheme`; the user's explicit choice is persisted in `localStorage`. Implement as CSS custom properties overridden under `[data-theme="dark"]` on the root. Dark theme keeps the SAME 60/30/10 discipline and the SAME accent reserved-for rule — only the values change. Accent switches to **amber**.

| Role | CSS var | Light value | Dark value |
|------|---------|-------------|------------|
| Dominant (60%) | `--color-surface` | `#F5F6F8` | `#0F172A` |
| Secondary (30%) | `--color-panel` | `#FFFFFF` | `#1E293B` |
| Accent (10%) | `--color-accent` | `#2563EB` | `#F59E0B` (amber-500) |
| Accent hover | `--color-accent-hover` | `#1D4ED8` | `#D97706` (amber-600) |
| Destructive | `--color-danger` | `#DC2626` | `#F87171` |
| Text primary | `--color-text` | `#1F2933` | `#E5E7EB` |
| Text secondary | `--color-text-muted` | `#6B7280` | `#94A3B8` |
| Border / divider | `--color-border` | `#D9DCE1` | `#334155` |

Toolbar carries a theme toggle control (icon button, `aria-label` 切換深淺色模式 / "Toggle light/dark theme"). Exact dark surface shades and toggle icon/placement are Claude's discretion per 01-CONTEXT.md, keeping the professional-minimalist tone.

### Empty state (before any file is loaded)

| Element | Copy (繁體中文) | Gloss |
|---------|----------------|-------|
| Empty state heading | 上傳 PDF 以開始 | "Upload a PDF to begin" |
| Empty state body | 選擇或拖曳一個供應商 PDF 檔案,即可在此預覽各頁內容。原始檔案不會被更動。 | "Choose or drag a supplier PDF to preview its pages here. Your original file is never modified." (reassures on the UPLOAD-04 preservation guarantee) |

### Loading states

| Element | Copy (繁體中文) | Gloss |
|---------|----------------|-------|
| Uploading | 正在上傳檔案… | "Uploading file…" |
| Rendering pages (server rasterizing) | 正在處理檔案,準備預覽… | "Processing file, preparing preview…" |
| Single page loading (paging to a not-yet-rendered page) | 載入中… | "Loading…" (inline on the page stage) |

### Error state (invalid or failed file)

Pattern for every error: **problem (what went wrong) + solution path (what to do next)**. Errors render as an inline block on the stage/dropzone (non-blocking), with a 重試 (retry) affordance where applicable.

| Case | Copy (繁體中文) | Gloss |
|------|----------------|-------|
| Error heading (generic) | 無法開啟此檔案 | "Couldn't open this file" |
| Unsupported file type | 此檔案格式不支援。請改用 PDF 檔案後再試一次。 | "This file type isn't supported. Please use a PDF file and try again." |
| Corrupt / unreadable PDF | 這個 PDF 檔案無法讀取,可能已損毀。請確認檔案後再試一次。 | "This PDF can't be read and may be damaged. Check the file and try again." |
| File too large | 檔案超過大小上限({limit})。請改用較小的檔案。 | "File exceeds the size limit ({limit}). Please use a smaller file." — `{limit}` injected from backend config |
| Upload / network failure | 上傳失敗,請檢查網路連線後再試一次。 | "Upload failed. Check your connection and try again." |
| Page render failure | 此頁無法顯示。請重新整理或更換檔案。 | "This page can't be displayed. Refresh or replace the file." |
| Retry action | 重試 | "Retry" |

### Destructive actions

| Element | Copy (繁體中文) | Gloss |
|---------|----------------|-------|
| (none — true destructive) | — | Phase 1 has NO destructive actions. Region removal / logo placement (the destructive/mutating operations) are Phases 2–4. Original files are never mutated (server keeps originals/ immutable), so nothing in this phase deletes user data. |
| Soft confirmation — replace loaded file | 更換檔案會清除目前的預覽,確定要繼續嗎?〔取消／更換〕 | "Replacing the file will clear the current preview. Continue? [Cancel / Replace]" — shown ONLY if a file is already loaded; this is a discard-current-view guard, not data deletion. (default — confirm later; may be dropped if deemed unnecessary friction) |

## Layout & Interaction Contract

- **Primary focal point per state:** In the EMPTY / upload state, the upload dropzone's primary CTA (`選擇 PDF 檔案`, accent-colored) is the single primary visual anchor — centered, the largest accent element on screen. In the LOADED / preview state, the page-stage image is the primary focal point (largest element, paper-sheet shadow on the neutral `--color-surface` backdrop); the toolbar is secondary chrome and the active page indicator is the only other accent and is intentionally small. One clear anchor per state — never two competing focal points.
- **App shell grid (forward-compatible):** `toolbar` row across the top; below it a two-column main area — `[ preview stage (1fr) | side panel (0 / collapsed in Phase 1) ]`. The side-panel column is declared now (e.g. `grid-template-columns: 1fr 0;` collapsing to `1fr` ) so Phase 2 (region list) and Phase 3 (logo picker) expand it to a fixed width (e.g. ~320px) with no structural change.
- **Page stage as overlay host:** the page image lives inside a `position: relative` stage wrapper sized to the rendered image. Phase 2's transparent `<canvas>`/`<div>` overlay will be `position: absolute; inset: 0` over this wrapper — so Phase 1 must NOT bake the image directly into a flow that prevents absolute positioning.
- **Coordinate-fidelity note (carry-forward, not built here):** because later phases map browser-image pixels → PDF points, the displayed page image must be rendered/scaled by a known factor and never letterboxed in a way that detaches displayed pixels from the server render. Keep the stage measuring the true image box. (Mechanics are Phase 2; this is only a layout caution.)
- **Keyboard:** Left/Right arrows page prev/next when the stage has focus; `+`/`-` zoom; all controls reachable by Tab with a visible focus ring. (default — confirm later)
- **Responsiveness:** Desktop-first (internal LAN, Chrome/Edge/Firefox). Single breakpoint guard so the toolbar wraps gracefully under ~720px; no mobile-native layout (out of scope per REQUIREMENTS).
- **Empty → loading → loaded → error** is the single state machine for the stage; only one is visible at a time.
