# Phase 3 — UI Design Contract

> Visual and interaction contract for the 商標置入 (logo placement) phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **UI language:** All user-facing strings are Traditional Chinese (繁體中文). English glosses in parentheses are for the planner/executor only and MUST NOT ship in the UI.
>

Phase 2 (`02-UI-SPEC.md`) added the region overlay, side-panel region list, before/after toggle (`原圖 / 移除結果`), and the single-accent action group with its "編輯使結果失效 → 重新套用" stale machinery. **This document does NOT redefine any of those tokens or components** — it references them (via the existing `web/styles/tokens.css` custom properties) and specifies ONLY the NEW Phase 3 surfaces: the side-panel logo picker, the result-label update, and how a logo change plugs into the existing stale/action-group state machine.
>
> **Autonomous run (--auto chain):** Phase 3 decisions were captured in `03-CONTEXT.md` (D-01…D-06, verified by `03-RESEARCH.md`); no live prompting. Locked decisions are the contract. Discretionary visual details (thumbnail grid layout, selected-state styling, picker placement within the side-panel) are reasonable defaults consistent with the established professional-minimalist system, marked **default — confirm later**. Where a value reads "see 01/02-UI-SPEC", the executor reuses the existing token/component unchanged.

## Phase Scope (what this contract covers)

Phase 3 adds the logo picker + logo-in-result ON TOP of Phase 2's region/removal/before-after/download UI. The contract covers exactly these NEW surfaces:

| Surface | In this phase | Notes |
|---------|---------------|-------|
| Logo picker — side-panel thumbnail grid (D-05) | Yes | A NEW section inside the existing `aside#side-panel`, below the region list. Single-select grid of the fixed logo library (transparent PNGs, multiple versions — D-03). Reuses the dual-theme tokens + 繁中文案. Catalog fetched once via `api.listLogos()` (the sole server seam). |

| Logo-picker empty state (D-04 / A2) | Yes | When the library is empty/absent (`GET /logos → {logos: []}`), the grid shows a 繁中 empty state and the flow degrades to pure removal (Phase 2 behavior); nothing blocks. |
| Result label update — `移除結果` → `移除+置入結果` (D-06) | Yes | The Phase-2 before/after toggle's "after" segment relabels to reflect that the result now shows removal **and** the placed logo. The toggle mechanics are otherwise unchanged (single-page swap; same `/result/.../image` URL — zero new rendering). |
| Logo-change → result stale (Pitfall 5) | Yes | Selecting or changing the logo (incl. clearing the selection) invalidates a fresh result exactly like a region edit, reusing the Phase-2 `onRegionsEdited`-style machinery (`resultFresh = false`, demote to `重新套用`, stale notice, download disabled). |
| Action-group integration (D-01 global logo) | Yes | The logo selection is part of the SAME single flow. Exactly ONE accent-filled button at a time stays true (`套用移除` → `下載 PDF`). The logo `logo_id` rides along the existing `/process` POST; no new buttons in the action group. |
| Per-region logo / logo upload UI / drag-opacity-rotation controls / SVG | NO — deferred | Out of scope per `03-CONTEXT.md`. Do NOT design these. The picker layout chosen here must not preclude a future per-region or upload affordance, but must not build one now. |

**Forward-compatibility carried forward (load-bearing):** The Phase-2 region overlay, coordinate-fidelity seam (image-pixel rects → server-side PDF points), and the deferred-mutation flow are UNCHANGED. The logo is placed server-side on the SAME `pdf_rect` the removal already computed (D-02 contain+center, LOGO-02), so there is **no new client-side geometry** — the picker only contributes a `logo_id` to the job payload. The before/after toggle, action group, and stale machinery are extended in place, not re-architected.

## Color

Unchanged base palette — reuse the Phase 1/2 dual-theme tokens verbatim from `tokens.css`. The 60/30/10 split is preserved EXACTLY. Phase 3 introduces NO new color tokens for hues; it **extends the accent reserved-for list by one element** (the selected logo thumbnail) and uses existing neutrals for the grid chrome.

| Secondary (30%) | `--color-panel` | `#FFFFFF` | `#1E293B` | Logo-picker section fill (same side-panel surface as the region list) |

| Accent hover | `--color-accent-hover` | `#1D4ED8` | `#D97706` | Hover/active of the primary action button (unchanged); the selected thumbnail ring may deepen to this on hover |
| Destructive | `--color-danger` | `#DC2626` | `#F87171` | (Phase 2 only — `清除全部` / delete-region; Phase 3 adds no destructive action) |

**Accent reserved for (explicit — EXTENDED by exactly one element from Phase 2; restated so the checker can verify Phase 3 does not leak accent elsewhere):**
1. The **primary action** of the current step — `套用移除` (accent) until a fresh result exists, then `下載 PDF` (accent) and apply demotes to neutral `重新套用`. Only ONE accent-filled button visible at a time. (Unchanged from Phase 1/2.)
2. The **active / current page indicator** — the highlighted current page number. (Unchanged.)
3. **NEW — the SELECTED logo thumbnail** — exactly one thumbnail can be selected at a time (single-select, global logo D-01), and it is marked with the accent (a 2px accent ring/border, optionally an accent check badge). This is a single-selection affordance, semantically equal to "the active page indicator" (the one chosen item), so it fits the reserved-for discipline rather than violating it. **At most one accent thumbnail exists at any moment**, and it does not compete with the action-group accent because the two live in different regions and there is still only one accent CTA on screen.

Everything else in the picker (unselected thumbnails, their hover, the grid chrome, captions) uses neutral surfaces/borders — NOT the accent. Hover is `--color-neutral-hover`; the unselected border is `--color-border`.

### Thumbnail backing (transparent-PNG legibility — Pitfall 2)

Library logos are transparent PNGs (D-03), and many company marks are predominantly white/light or dark. To keep every logo legible in the picker in BOTH themes WITHOUT inventing a new color:
- Each thumbnail cell paints a **neutral `--color-surface` backing** behind the transparent PNG (light grey in light theme, deep slate in dark theme) — the same backdrop the page-stage uses for the PDF sheet. This avoids a "white logo on white panel → invisible" failure and a "dark logo on dark panel → invisible" failure.
- The PNG is rendered with `object-fit: contain` inside the cell (mirrors the D-02 contain behavior the server applies in the PDF), so the picker preview matches how the logo will be placed.
- **default — confirm later:** if a specific real logo still reads poorly on `--color-surface` in one theme, a subtle checkerboard or a per-cell mid-grey can be added; not built unless a real asset needs it.

### New tokens (appended to existing `tokens.css`)

Only two layout/scale variables are added — both theme-agnostic, no new hues (the picker reuses existing color tokens above).

```css
/* :root additions (theme-agnostic) — Phase 3 logo picker */
--logo-thumb-size: 72px;        /* thumbnail cell min square; grid auto-fills the 320px column */
--logo-grid-gap: var(--space-sm); /* 8px gap between thumbnail cells (alias for readability) */
```

The selected-ring color is NOT a new token — it is `var(--color-accent)` (already dual-themed). No `[data-theme="dark"]` override is needed for the new variables.

## Layout & Interaction Contract

- **Primary focal point per state (one anchor, never two competing — unchanged discipline):**
  - *Document loaded, picking a logo:* the page-stage image remains the focal point; the side-panel (region list + logo picker) is secondary chrome. The single accent-filled CTA is still `套用移除` (or disabled if 0 regions). The selected logo thumbnail carries the accent ring, but it is small, lives in the side-panel, and is a single-selection marker — it does NOT out-shout the one accent CTA, and there is never a second accent-filled *button*.
  - *Result ready (with logo):* the page-stage (toggleable `原圖` ↔ `移除+置入結果`) stays the focal point; the single accent CTA shifts to `下載 PDF`; the selected thumbnail keeps its accent ring (it reflects the logo that was applied). Still exactly one accent CTA + one selected-item marker + the page indicator.
  - In every state there is exactly ONE accent-filled action button; the selected-thumbnail ring and the active-page-indicator are single-selection markers, consistent with the reserved-for rule.
- **Picker placement within the side-panel (D-05, A3):** the logo picker is a NEW section BELOW the region list inside the same `aside#side-panel`. Rationale: the region list is the user's first action (frame areas to remove) and naturally tops the panel (matching the Phase-2 layout); the logo choice is the next step and reads top-to-bottom as "remove here → place this". The picker section shares the panel's scroll. **default — confirm later** (a tabbed panel or picker-above-list is functionally equivalent; below-list is the recommended default and keeps Phase-2 layout stable).
- **Single global logo, single flow (D-01):** there is ONE logo selection for the whole job. The picker holds `selectedLogoId` (client state); it is included as `logo_id` in the existing `api.processJob(...)` body (`{ dpi, regions, logo_id }`). No logo selected ⇒ `logo_id` omitted/null ⇒ pure removal (Phase-2 behavior preserved). The action group remains the Phase-2 state machine verbatim — the logo does NOT add or remove buttons.
- **Logo change ⇒ result stale (Pitfall 5 — load-bearing):** selecting a logo, changing to a different logo, or choosing `不置入商標` is a **job-input change** and MUST invalidate a fresh result exactly like a region edit. The executor calls the same `onRegionsEdited()`-style path (set `resultFresh = false`; if currently viewing the result, drop back to `原圖`; show the stale notice `框選已變更,請重新套用以更新結果`; demote `下載 PDF` → disabled and `重新套用` → accent). **default — confirm later:** the stale-notice copy currently says "框選已變更" (selections changed); when the trigger was a *logo* change the executor MAY use a logo-specific variant — recommended copy: `所選商標已變更,請重新套用以更新結果` ("Selected logo changed — re-apply to update the result") — to be honest about *what* changed. Either is acceptable; the logo-specific variant is preferred for clarity.
- **Conditional result relabel (D-06):** the `#view-result` segment shows `移除+置入結果` when `logo_id` is set and `移除結果` when it is null (so the label never promises a logo that wasn't placed). The accessible label `切換處理前後對照` is used in both cases. The toggle mechanics (single-page swap to `api.resultImageURL(...)`, overlay hidden in result mode) are UNCHANGED — the work-copy render already contains the logo, so there is **zero new rendering** (D-06). The executor must verify the longer `移除+置入結果` string fits the segmented control; if the toolbar is tight at narrow widths, the segment may wrap or the toolbar group reflows per the Phase-2 responsive rule.
- **Coordinate fidelity unchanged:** the logo is placed server-side on the SAME `pdf_rect` the removal computed (D-02 contain+center). The browser contributes NO geometry for the logo — only the `logo_id`. The Phase-2 image-pixel → PDF-point seam is untouched.
- **Thumbnail interaction:** click or Enter/Space on a thumbnail selects it (single-select; previous deselects). The grid is keyboard-navigable: each thumbnail is Tab-reachable with the focus ring; arrow-key roving within the grid is **default — confirm later** (nice-to-have; Tab-through is the baseline). Selecting a thumbnail must not steal focus from or interfere with the region overlay (different region of the DOM; the overlay's pointer capture is scoped to `#page-frame`).
- **Empty-library graceful degradation (A2):** if the library is empty/absent, the picker shows its empty state and the user proceeds with pure removal — `套用移除` / `下載 PDF` work exactly as in Phase 2. No logo-related control blocks the flow; `GET /logos` returning `{logos: []}` is a normal state, not an error.
- **Responsiveness:** Desktop-first (internal LAN). The picker shares the Phase-2 side-panel responsive behavior (fixed 320px column on desktop; stacks/drawer below ~720px). The thumbnail grid `auto-fill` reflows column count to the available width automatically. No mobile-native layout (out of scope).
- **State machine:** the picker is active only within the `loaded` stage state (alongside the region UI). On reset (`resetRegions` / new upload), the picker clears `selectedLogoId` and re-fetches/re-renders the catalog (or reuses the cached catalog — the library is fixed, so a one-time fetch per page load is fine; the selection resets per session).
