# Phase 2 — UI Design Contract

> Visual and interaction contract for the 框選與真正移除(向量)+ 下載 (region selection, true removal, before/after, download) phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **UI language:** All user-facing strings are Traditional Chinese (繁體中文). English glosses in parentheses are for the planner/executor only and MUST NOT ship in the UI.
>
> **This is an EXTENSION contract.** Phase 1 (`01-UI-SPEC.md`, approved 2026-05-22) established the FOUNDATIONAL token set, dual light/dark theme, copywriting conventions, page-stage overlay host, and reserved side-panel. This document does NOT redefine those tokens — it references them and specifies ONLY the NEW Phase 2 surfaces. Where a value reads "see 01-UI-SPEC", the executor reuses the existing `tokens.css` custom property unchanged.
>
> **Non-interactive run:** Phase 2 decisions were captured in `02-CONTEXT.md`; the researcher could not prompt the user. Locked decisions (D-01…D-07) are used as the contract. Discretionary visual details (region-rectangle colors per theme, control placement, status-indicator styling) are reasonable defaults consistent with Phase 1's professional-minimalist system, marked "default — confirm later".

## Phase Scope (what this contract covers)

Phase 2 adds region selection + true removal + before/after + download ON TOP of Phase 1's server-rendered single-page preview. The contract covers exactly these NEW surfaces:

| Surface | In this phase | Notes |
|---------|---------------|-------|
| Region-drawing overlay (transparent layer over the page `<img>`) | Yes | Click-drag to draw a rectangle on the page-stage. Multiple regions per page; **regions may overlap** (D-01). **NO resize/move handles** — draw-wrong → delete & redraw (D-01). Stored client-side in IMAGE-pixel space (deferred-mutation, D-05). |
| Region list (in the reserved right side-panel) | Yes | Per-page list of the current page's regions; **delete a single region**; **clear all** (D-01). Cross-page: each page keeps its own list (D-02). The side-panel column (collapsed `0` in Phase 1) expands here. |
| Before/after toggle | Yes | A single control that switches the page-stage between **原圖 (original render)** and **移除結果 (removal-result render)** (D-04). **Single-page toggle — NOT side-by-side, NOT a slider.** The "result" image is the server's render of the work-copy after redaction (D-05). |
| Apply / preview-removal action | Yes | Triggers the server to apply redaction on the work-copy and produce the result render so the before/after toggle has something to show (D-05). The original file is never mutated. |
| Download action | Yes | Downloads the output PDF. Filename = `原名_logoswap.pdf` (D-06). All pages kept, including unmodified pages (D-07). |
| Region-count / status indicator | Yes (small) | A compact "已框選 N 個區域" indicator + result/stale status. Secondary chrome, not a focal point. |
| Logo placement / raster-image fill | NO — Phases 3–4 | Do NOT design here. The side-panel and toolbar layout chosen here MUST leave room for Phase 3's logo picker without re-architecting. |

**Forward-compatibility carried forward (load-bearing):** The Phase 1 page-stage is already `position: relative` and the `#page-frame` wrapper is sized imperatively to the TRUE render box (the exact server PNG box, never letterboxed). Phase 2's overlay MUST be a child of `#page-frame` with `position: absolute; inset: 0` so overlay pixels stay attached to the render box across zoom (CSS-scale) and paging. The side-panel must remain a reusable column so Phase 3's logo picker drops in.

### Region rectangle treatment (NEW — D-01; the distinct, theme-aware, non-accent selection visual)

Region rectangles must be clearly visible over arbitrary CAD/document content in both themes WITHOUT consuming the reserved accent. They use a dedicated neutral-cool "selection" hue (slate/blue-grey) that reads as "tool overlay", distinct from the blue/amber action accent. **default — confirm later.**

| State | Treatment (light) | Treatment (dark) | Notes |
|-------|-------------------|------------------|-------|
| Committed region (idle) | 2px solid border `--color-region-border` `#475569` (slate-600); fill `--color-region-fill` `rgba(71,85,105,0.14)` | border `#CBD5E1` (slate-300); fill `rgba(203,213,225,0.16)` | Semi-transparent fill so underlying content stays visible (user must judge over/under-removal). Overlapping regions stack their translucent fills — overlap is allowed and visible (D-01). |
| Region being drawn (drag in progress) | Same border, fill `rgba(71,85,105,0.10)`, border `1px dashed` | Same, `1px dashed` `#CBD5E1` | Dashed while dragging; solidifies to 2px on mouse-up (commit). |
| Hovered/selected region (its list row is hovered/focused) | Border thickens to 2px and uses `--color-region-border-strong` `#1E293B`; a small region-number badge shows top-left | Border `#E2E8F0`; badge top-left | Hovering a list row highlights the matching rectangle and vice-versa (bidirectional). Badge shows the region's ordinal "1", "2"… in `--font-size-label`, tabular-nums. |
| Result mode (showing 移除結果) | Overlay rectangles are HIDDEN | same | In the "after" view the regions are gone (the content is removed); showing them would re-clutter what the user is verifying. Toggling back to 原圖 restores them. |

These region colors are NOT part of the 10% accent budget — they are a tool-overlay treatment, intentionally cool/neutral and visually subordinate to the single accent CTA. They are not used anywhere else.

## Layout & Interaction Contract

- **Primary focal point per state (one anchor, never two competing):**
  - *Document loaded, 0 regions:* the page-stage image remains the focal point; the side-panel shows its empty state inviting a draw. The accent budget is just the active page indicator (apply is disabled/non-accent). The drawing hint (`在頁面上拖曳以框選…`) appears subtly on/under the stage.
  - *Regions drawn, not yet applied:* the page-stage with its overlay rectangles is the focal point; the single accent element is the **套用移除** CTA. The region list is secondary.
  - *Result ready:* the page-stage (now toggleable original↔result) stays the focal point; the single accent element shifts to **下載 PDF**. Apply demotes to neutral. The before/after toggle is prominent but neutral-styled chrome.
  - In every state there is exactly ONE accent-filled action and the page-stage is the largest element. The region rectangles are deliberately cool/translucent so they never out-shout the accent CTA.
- **Overlay pins to the true render box:** the overlay is a child of `#page-frame` (already sized imperatively by `viewer.js` to `renderBox × zoomFactor`). Because zoom is CSS-scale (D-02), the overlay and its rectangles scale with the frame automatically when stored as fractions/derived from the frame box; the executor MUST keep region coordinates anchored to the render box (not the viewport) so a region drawn at 100% still maps correctly at 150% and when the job spec (image pixels at the known render DPI) is sent to the server. This is the coordinate-fidelity seam (ARCHITECTURE Pattern 2 / PITFALLS 1–2): the browser holds image-pixel rects; the server is the only place that converts to PDF points.
- **Per-page region scope (D-02):** paging (Phase 1 prev/next/jump) swaps which page's regions are shown in BOTH the overlay and the list. Drawing on page 3 does not affect page 1. The per-page scope note + count update on page change.
- **Before/after is a single-page toggle (D-04), never side-by-side / slider:** the toggle swaps the `#page-image` src between the original render URL and the result render URL (the server's render of the redacted work-copy, D-05). The page does not split; only the displayed image and the overlay visibility change (overlay hidden in result mode).
- **Deferred-mutation flow (D-05) — the gated sequence:** draw region(s) → 套用移除 (server applies redaction to the work-copy, returns a result render) → toggle 移除結果 to verify → if wrong, toggle back to 原圖, delete/redraw, re-apply → 下載 PDF. Editing regions after a result exists marks the result **stale** (status notice + apply becomes 重新套用); download is allowed only against a fresh result.
- **App shell grid (forward-compatible, reuse Phase 1):** toolbar row across the top; main = `[ page-stage 1fr | side-panel ]`. Phase 2 expands the reserved side-panel column from `0` to `--side-panel-width` (320px) when a document is loaded (`grid-template-columns: 1fr var(--side-panel-width)`), collapsing back to `1fr 0` with no document. No structural change; Phase 3's logo picker reuses the same column.
- **Keyboard:** Phase 1's stage keyboard (←/→ paging, +/− zoom) is preserved. NEW: `Delete`/`Backspace` deletes the currently selected region when a region row (or its rectangle) has focus; `Escape` cancels an in-progress drag; region rows are Tab-reachable with the focus ring. Pointer drawing must not hijack the jump-input or buttons. (default — confirm later)
- **Pointer / drawing detail:** a minimum drag threshold (e.g. ~4px) prevents accidental zero-size regions from a stray click; sub-threshold drags are ignored (no region created). Cursor over the overlay is `crosshair` to signal draw mode. (default — confirm later)
- **Responsiveness:** Desktop-first (internal LAN). Below ~720px the side-panel may stack under the stage or become a toggleable drawer rather than a fixed 320px column (reuse Phase 1's single breakpoint; executor's call). The before/after toggle and action group wrap with the toolbar. No mobile-native layout (out of scope per REQUIREMENTS).
- **State machine extension:** Phase 1's stage states (empty | uploading | loaded | error) are unchanged; the overlay, side-panel, before/after toggle, and action group are active only within the **loaded** state and are hidden/collapsed otherwise.

## Defaults Requiring Later Confirmation

Because this ran non-interactively (Phase 2 decisions came from `02-CONTEXT.md`; no live prompting), the following discretionary visual/interaction details are reasonable defaults the team should confirm during planning/review. All are consistent with Phase 1's professional-minimalist system and the locked Phase 2 decisions.

1. **Region rectangle colors** — slate/cool-grey border + translucent fill per theme (light `#475569` / dark `#CBD5E1`), chosen to be visible over CAD content WITHOUT touching the reserved accent. Confirm the exact hues/opacities read well over real supplier drawings.
2. **Overlay implementation** — absolutely-positioned `<div>` rectangles (recommended for hover/focus/a11y) vs a single `<canvas>`. Functionally equivalent for the contract.
3. **Action-group placement** — toolbar-right (next to the before/after toggle and theme toggle) vs side-panel footer. Default: toolbar-right.
4. **Before/after toggle form** — two-segment segmented control vs a labeled switch. Default: segmented (原圖 / 移除結果).
5. **Drag threshold + cursor** — ~4px minimum drag to commit; `crosshair` cursor over the overlay.
6. **Delete-region keyboard** — `Delete`/`Backspace` on a focused region; `Escape` cancels a drag.
7. **Single-region delete has no confirmation** (immediate); only **清除全部** confirms. Confirm this matches the draw-wrong→delete&redraw philosophy (D-01).
8. **Stale-result handling** — editing regions after a result exists marks it stale and requires 重新套用 before download. Confirm this is the desired guard vs auto-re-applying.
9. **Responsive side-panel** — fixed 320px column on desktop; stacks/drawer below ~720px. Confirm the small-viewport behavior.
